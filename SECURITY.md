# Security Policy

> [!CAUTION]
> **Do not report security vulnerabilities through GitHub issues or any other
> public medium.**

> [!WARNING]
> **Tascarrel is under active development.** Things may break, and its security
> properties have not been independently audited.

We welcome private reports of potential security vulnerabilities.

> [!TIP]
> Before reporting a vulnerability, read the
> [architecture's security model](ARCHITECTURE.md#security-model) to understand
> Tascarrel's intended trust boundaries, accepted risks, and security non-goals.

## Reporting a Vulnerability

Send reports to **security@silitics.com**. Include enough technical detail to
validate the issue, ideally including reproduction steps, the affected commit or
release, the execution environment, the expected security boundary, and the
observed impact.

Use the public issue tracker for general bugs and feature requests.

### What to Expect

Reports are reviewed on a best-effort basis. We do not promise an
acknowledgement time, assessment time, fix, security update, coordinated
disclosure process, or publication timeline. We may contact you for additional
information. If we fix and disclose a reported vulnerability, we may credit you
with your permission.
